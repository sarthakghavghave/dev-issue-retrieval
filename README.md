# Dev Issue Retrieval

A full-stack semantic search platform for discovering relevant developer issues and technical discussions from open-source repositories.

Live Demo: https://spring-ccmb.onrender.com/

## Overview

Dev Issue Retrieval enables developers to search historical GitHub issues using natural language instead of exact keywords.

The system ingests issue data, generates semantic embeddings, indexes them with FAISS, and retrieves the most relevant results using vector similarity search and cross-encoder reranking.

## Features

* Semantic issue search using natural language queries
* Dense vector retrieval with FAISS
* Cross-encoder reranking using TinyBERT
* Spring Boot web application
* FastAPI NLP service
* Dockerized deployment
* Repository-aware search results
* Issue metadata and source links
* Cloud deployment on Render

## System Architecture

The system consists of two stages:

### 1. Offline Indexing Pipeline

A historical dataset of GitHub issues is collected and processed before deployment.

```text
GitHub Issues
      ↓
Historical Ingestion
      ↓
Preprocessing & Cleaning
      ↓
Embedding Generation (BGE Small)
      ↓
FAISS Index Creation
      ↓
Persisted Index + Metadata
```

Artifacts generated by the indexing pipeline:

* FAISS vector index
* Issue embeddings
* Metadata store

These artifacts are created offline and loaded by the retrieval service during startup.

### 2. Online Retrieval Pipeline

When a user submits a search query:

```text
User Query
      ↓
Spring Boot Web UI
      ↓
FastAPI Retrieval Service
      ↓
Query Embedding (BGE Small)
      ↓
FAISS Candidate Retrieval
      ↓
TinyBERT Cross-Encoder Reranking
      ↓
Ranked Results
```

The query is converted into an embedding and searched against the pre-built vector index. The most relevant candidates are then reranked and returned to the user.

## Retrieval Pipeline

### Offline Stage

1. Historical GitHub issue ingestion
2. Data preprocessing and cleaning
3. Retrieval text generation
4. Embedding generation using BGE Small
5. FAISS index creation
6. Metadata persistence

### Online Stage

1. User submits natural language query
2. Query embedding generation
3. Top-K FAISS retrieval
4. TinyBERT reranking
5. Result presentation

## Dataset

Current indexed dataset:

* ~5,500 curated GitHub issues
* Multiple open-source repositories
* Preprocessed and deduplicated issue content
* Metadata enrichment including labels, repository, URLs, and timestamps

## Local Development

### Start NLP Service

```bash
cd nlp-service
uvicorn scripts.retrieval_api:app --reload
```

### Start Spring Boot

```bash
cd backend
mvn spring-boot:run
```

### Docker

```bash
docker compose up --build
```
